Entity Relationships

Users → Tenants: One-to-One (1:1)
Each user can be one tenant, each tenant has one user account
Rooms → Contracts: One-to-Many (1:N)
One room can have multiple contracts over time
Contracts → Tenants: Many-to-Many (M:N)
Multiple tenants can share one contract via contract_tenants
Contracts → Deposit Entries: One-to-Many (1:N)
One contract can have multiple deposit transactions
Contracts → Invoices: One-to-Many (1:N)
One contract generates monthly invoices
Invoices → Tenant Payments: One-to-Many (1:N)
One invoice split into payments per tenant
Invoices → Payments: One-to-Many (1:N)
One invoice can have multiple payment transactions
Rooms → Meter Readings: One-to-Many (1:N)
One room has monthly electricity readings
Tenants → Laundry Orders: One-to-Many (1:N)
One tenant can place multiple laundry orders
Laundry Orders → Order Items: One-to-Many (1:N)
One order contains multiple service items
Services → Service Prices: One-to-Many (1:N)
One service has different prices per customer type
Users → Multiple Entities: One-to-Many (1:N)
Users create/record contracts, invoices, payments, readings
